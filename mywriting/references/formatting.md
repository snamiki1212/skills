# 整形

表記の機械的ルール。日本語の文章を書く・表記を整えるときに適用する。

- 一文ごとに改行する。段落の区切りは空行で示す。
- コード、差分、ログ、設定ファイルの断片はコードブロックで示す。
- 用語の由来や定式化の名称など、本筋から一段外れる補足は、本文に並べず脚注（`[^ラベル]`）に降ろす。
- 定義や分類の列挙は箇条書きで示してよい。定義される用語は太字にする。
- 用語を本文中で初めて定義・導入するときも、その語は太字にする。すでに導入した語を話題として指すとき、引用、通称には「」を使い、太字と使い分ける（初出の定義は太字、以後の言及は「」）。
- 定義・導入以外での本文中の太字強調を多用しない。誤読を防ぐ否定や節の帰結など、論理の要所に限り、一節に一、二箇所まで使ってよい（導入部でも可）。それ以外は文の順序と構造で際立たせる。
- ダッシュを日本語の地の文・見出しで使わない。対象は em ダッシュ `—`、horizontal bar `―`、いわゆる2倍ダッシュ「——」。
  - 短い同格の挿入（「A——挿入——B」）は括弧（）に置き換える。
  - 説明の挿入や言い換え・敷衍（「A——B」）は、句点で二文に分けるか読点でつなぐ。
  - 範囲を示す en ダッシュ `–`、英語の複合語（`Curry–Howard` など）、コードブロック、書誌情報は対象外。
- 並列の列挙は、「AやB」のように助詞でつながず、中黒（「A・B」）か読点（「A、B」）で書く。区切りが記号として見え、視覚的に追いやすい。
- 文の途中の括弧に長い列挙を入れない。（）内の並列は 3 項目までを目安にし、超えるなら括弧をやめて地の文の列挙・箇条書き・テーブルに出す。括弧が長いほど文の再開点が遠のき、読者は括弧の前の文脈を保持できなくなる。文末に添える括弧は、再開する文が残らないので、この目安より長くてよい。
- 列挙を入れ子にしない。列挙の項目に（）でさらに列挙をぶら下げると、読者は自分がどの階層を読んでいるかを追わされる。二段目が必要なら、箇条書きのネストやテーブルなど、階層が目に見える形に直す。
- 見出し・コラム見出しに、区切り線（罫線 `─` U+2500 やダッシュ類）で「種別──主題」「主題──概念」のように二要素を詰め込まない。見出しは単一の自然な句にする（要素を一つに絞るか、助詞・読点でつなぐ）。コラム見出しも「基礎」「補足」のような種別名だけで済ませず、「同値関係としての分類」「ループ不変条件と帰納法」のように内容を特定する。
- 用語とその定義を並べる箇条書きは、区切り線ではなく全角コロンで「**用語**：説明」と書く。
- 変更点や要点を箇条書きで列挙するときのラベル（「ラベル：説明」の左辺）は、話題名でなく結論を書く。ラベル単体で「何がどうなったか」がわかる句にする。動詞・述語、または動作・変化を表すサ変名詞（「中間テーブル化」など）で書き、体言でトピックを指すだけ（「〜の構造：」「〜について：」）や、情報量のない汎用語（「更新：」「対応：」）にしない。悪い例：「ラベリングの構造：activity と Value を id で結ぶ」。良い例：「ラベリングを中間テーブル化：activity と Value を id で結ぶ」。
- 名前と説明が対で揃う並列要素（項目とその定義、対応関係など）を数多く並べるときは、ネストした箇条書きではなくテーブルにする。縦に揃って見比べやすい。書籍の地の文では多用せず、比較・対応が主眼のときに使う。
