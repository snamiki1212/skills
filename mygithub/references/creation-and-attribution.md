# PR・Issue の作成、PR のマージと AI 操作の帰属

## 作業依頼の完了

ユーザーから実装・修正などの作業を依頼されたら、ローカルでの変更だけで完了とせず、コミット、push、PR の作成または更新まで行う。
対象の作業に対応する Open PR がすでにある場合は、その PR のブランチに変更をコミットして push し、必要に応じて PR の本文も更新する。
既存 PR がある作業で、同じ変更を含む新しい PR を作成しない。

ただし、ユーザーが PR を作成しないよう明示した場合、または依頼が相談・調査・報告だけで変更を含まない場合は、PR を作成または更新しない。

## PR 作成前の main 確認

PR を作成する前に `git fetch origin main` を実行し、`git diff origin/main...HEAD` で `main` との差分を確認する。
`main` に同じ変更がすでに取り込まれており、PR に含める差分がない場合は、PR を作成せずその旨をユーザーへ報告する。

## 作業完了後の PR 作成

ユーザーから実装・修正などの作業を依頼され、変更をコミットして push できる状態になったら、PR をすぐに作成する。
ユーザーは作業内容の確認を PR ベースで行うため、PR 作成の要否を確認するためだけに作業を止めない。

ただし、ユーザーが PR を作らないよう明示した場合、または依頼が相談・調査・報告だけで変更を含まない場合は作成しない。

PR または Issue を作成したら、ユーザーへの完了報告に番号だけを書かない。
作成した PR・Issue の URL を必ず Markdown link または URL として表示する。

```markdown
作成しました: [PR #123](https://github.com/owner/repo/pull/123)
```

PR テンプレートがないなどの理由で PR 本文を自由入力し、AI を介して PR を作成するときは、本文の末尾に実行主体を追記する。
誰が本文を作成したかを後から識別できるよう、製品名を記す。
実行中のモデル名を確認できる場合は、系列名・世代・バージョン・派生名をすべて含める。
`5.6 Terra` のような情報を省略しない。

```text
Posted by Claude Code (Opus 5.6 Terra)
```

Codex CLI では `/status` で実行中のモデル名を確認する。
ほかの実行環境では、セッションから確認できる情報だけを使う。
モデル名を確認できない場合は、`Posted by Codex` のように製品名だけを記載し、推測で補わない。
PR テンプレートがある場合は、そのテンプレートの指示を優先する。

## PR のマージ

ユーザーから PR のマージを依頼されたら、マージの完了後にマージ元のリモートブランチを削除する。
ローカルのマージ元ブランチは、現在チェックアウトされておらず、未コミットの変更を失わないと確認できる場合に削除する。
ブランチの削除を妨げる未コミット変更などがある場合は、マージを妨げず、削除できなかった理由をユーザーへ報告する。

AI を介して GitHub にコメントまたはレビューを投稿するときは、投稿本文の末尾に実行主体を追記する。
誰が操作したかを後から識別できるよう、製品名を記す。
実行中のモデル名を確認できる場合は、系列名・世代・バージョン・派生名をすべて含める。

```text
Posted by Codex (GPT-5.6 Terra)
```

Codex CLI では `/status` で実行中のモデル名を確認する。
ほかの実行環境では、セッションから確認できる情報だけを使う。
モデル名を確認できない場合は、`Posted by Codex` のように製品名だけを記載し、推測で補わない。
人間が直接投稿するコメントには、この帰属を付けない。
