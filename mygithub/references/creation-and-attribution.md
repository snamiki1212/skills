# PR・Issue の作成と AI 操作の帰属

## 作業完了後の PR 作成

ユーザーから実装・修正などの作業を依頼され、変更をコミットして push できる状態になったら、PR をすぐに作成する。
ユーザーは作業内容の確認を PR ベースで行うため、PR 作成の要否を確認するためだけに作業を止めない。

ただし、ユーザーが PR を作らないよう明示した場合、または依頼が相談・調査・報告だけで変更を含まない場合は作成しない。

PR または Issue を作成したら、ユーザーへの完了報告に番号だけを書かない。
作成した PR・Issue の URL を必ず Markdown link または URL として表示する。

```markdown
作成しました: [PR #123](https://github.com/owner/repo/pull/123)
```

AI を介して GitHub にコメントまたはレビューを投稿するときは、投稿本文の末尾に実行主体を追記する。
誰が操作したかを後から識別できるように、製品名とモデルの完全な名称を記す。
モデル名は系列名へ丸めず、バージョン・バリアント・接尾辞を省略しない。

```text
Posted by Codex (GPT-5.6 Terra)
```

製品名またはモデル名の一方しか分からない場合は、分かる情報だけを書き、推測で補わない。
人間が直接投稿するコメントには、この帰属を付けない。
